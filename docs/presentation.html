05 • Concurrency Engineering Slide 06 / 18

Double-Booking Elimination via Pessimistic Locking

Row-level database write locks (SELECT ... FOR UPDATE) preventing appointment booking race conditions.

// 1. Repository with Pessimistic Write Lock
@Repository
public interface DoctorSlotRepository 
    extends JpaRepository<DoctorSlot, UUID> {

  @Lock(LockModeType.PESSIMISTIC_WRITE)
  @Query("SELECT s FROM DoctorSlot s " +
         "WHERE s.id = :slotId AND s.isBooked = false")
  Optional<DoctorSlot> findSlotForBookingWithLock(
      @Param("slotId") UUID slotId);
}

// 2. Transactional Booking Execution
@Transactional
public AppointmentResponse bookAppointment(...) {
  DoctorSlot slot = slotRepository
      .findSlotForBookingWithLock(request.slotId())
      .orElseThrow(() -> new SlotAlreadyBookedException(
          "This slot is no longer available."));

  slot.setBooked(true);
  slotRepository.save(slot);
  return AppointmentResponse.fromEntity(
      appointmentRepository.save(appointment));
}

Thread 1 (`t = 0.000s`) — SUCCESS (200 OK)

Acquires exclusive database row write lock • Marks isBooked = true • Commits transaction safely.

Thread 2 (`t = 0.002s`) — REJECTED (409 CONFLICT)

Waits on row lock • Reads committed state (already booked) • Throws SlotAlreadyBookedException cleanly without race condition.

06 • Security & RBAC Slide 07 / 18

Spring Security 6 Stateless RBAC Gateway

Granular method-level security, token signature verification, and zero server-side session state.

@Configuration
@EnableMethodSecurity
public class SecurityConfig {

  @Bean
  public SecurityFilterChain securityFilterChain(
      HttpSecurity http) throws Exception {
    http
      .csrf(AbstractHttpConfigurer::disable)
      .sessionManagement(s -> s.sessionCreationPolicy(
          SessionCreationPolicy.STATELESS))
      .authorizeHttpRequests(auth -> auth
        .requestMatchers("/api/v1/auth/**", 
                         "/swagger-ui/**", 
                         "/v3/api-docs/**").permitAll()
        .requestMatchers("/api/v1/admin/**").hasRole("ADMIN")
        .requestMatchers("/api/v1/doctor/**").hasRole("DOCTOR")
        .requestMatchers("/api/v1/patient/**").hasRole("PATIENT")
        .anyRequest().authenticated()
      )
      .addFilterBefore(jwtAuthenticationFilter, 
          UsernamePasswordAuthenticationFilter.class);

    return http.build();
  }
}

🔐 Core Security Pillars

  • Stateless Architecture: Enables horizontal cloud auto-scaling across Kubernetes nodes without sticky sessions.
  • Cryptographic JWT Parsing: HMAC-SHA256 signature verification extracts user identity, claims, and role authorities.
  • CORS Protection: Whitelisted frontend origins preventing cross-site scripting and unauthorized origin invocation.
  • BCrypt Salting: Irreversible password hashing with auto-generated work factor salt.
